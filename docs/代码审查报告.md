## 四、核心问题详细清单

### 4.1 实时链路 12 把锁的拓扑与死锁验证结论

对 `backend/api/assist/` 及关联模块全部 12 把锁进行了跨调用栈核查（异步锁 `http_lifecycle_lock`；线程锁 `_asr_state_lock`、`_dispatch_lock`/`_dispatch_changed`、`_commit_lock`、`_gen_lock`、`conversation_lock`、`mmpg_request.lock`、`LiveTranscript._lock`、`SingleMicSession._lock`、`RoleAudioInput._condition`、`RoleSwitch._lock`、`MmpgManager._audio_lock`）：

- **线程锁严格构成无环 DAG**：
  - `_asr_state_lock → _dispatch_lock`（[`pipeline.py:532-533,807,817,1611`](../backend/api/assist/pipeline.py#L532-L533)）
  - `_asr_state_lock → _commit_lock → mmpg_request.lock → conversation_lock → LiveTranscript._lock`（[`pipeline.py:650-655,1044-1047`](../backend/api/assist/pipeline.py#L650-L655) → [`scheduler.py:305`](../backend/api/assist/scheduler.py#L305) → [`answer_worker.py:1284,1392`](../backend/api/assist/answer_worker.py#L1392)）
  - `conversation_lock → SingleMicSession._lock → (RoleAudioInput._condition | MmpgManager._audio_lock | RoleSwitch._lock)`（[`session.py:416,463`](../backend/core/session.py#L416) → [`single_mic.py:152,186-267`](../backend/api/assist/single_mic.py#L186-L267)）
  - [`streaming.py:854,863`](../backend/services/llm/streaming.py#L854) 的 `run_coroutine_threadsafe(...).result()` 调用时不持有任何 Python 线程锁，不存在线程锁与事件循环互锁。
- **异步锁修复红线（重要）**：[`mmpg.py:877-887`](../backend/services/stt/mmpg.py#L877-L887) 在 `_run_transport` 中使用 `await asyncio.shield(start)`，且在 `except CancelledError` 中仍 `await start` 等待 `start_capture` 结束（从不取消 `start`）。因此，**修复 `mmpg_integration.start_capture` 的生命周期竞态时，严禁在 `start_capture` 内部 `await http_lifecycle_lock`**，否则当 `api_stop`/`api_pause`/`api_clear` 持有 `http_lifecycle_lock` 并执行 `await manager.stop()` 时将**必然发生异步死锁**。

### 4.2 P0 — 严重安全与运行时崩溃风险（必须立即修复）

#### P0-1 [安全/高危] Windows 驱动器相对路径绕过导致 KB 任意文件写入与任意文件删除
- **位置**：[`backend/api/kb/routes.py:115-163,183-191`](../backend/api/kb/routes.py#L115-L191)、[`backend/services/kb/indexer.py:159-169`](../backend/services/kb/indexer.py#L159-L169)
- **问题分析**：
  - `_safe_rel_path` 与 `kb_delete_doc` 仅校验 `is_absolute()`、`".." in parts` 及文件名不含 `/`/`\`。在 Windows 下，驱动器相对路径（如 `subdir="C:evil"`、`path="D:foo/bar.md"`，**甚至 `subdir=""` 时仅靠 `filename="C:evil.md"`**）的 `is_absolute()` 为 `False`、不含斜杠与 `".."`，但 `Path.drive` 非空；执行 `kb_dir / rel` 时 Python `pathlib` 会直接丢弃 `kb_dir`！
  - 实测复现输出：
    ```text
    sub='C:evil', fn='a.md'     -> rel=WindowsPath('C:evil/a.md')     drive='C:' is_abs=False resolved='C:\evil\a.md'
    sub='D:foo/bar', fn='a.md'  -> rel=WindowsPath('D:foo/bar/a.md')  drive='D:' is_abs=False resolved='D:\foo\bar\a.md'
    sub='', fn='C:evil.md'      -> rel=WindowsPath('C:evil.md')       drive='C:' is_abs=False resolved='C:\evil.md'
    ```
  - 任何可访问 API 的客户端（包括局域网已扫码终端）均可向任意盘符写入允许扩展名的文件，或经 `DELETE /api/kb/docs?path=C:target.txt` 调用 `full.unlink()` 删除任意文件；两处也未防 `kb_dir` 内符号链接逃逸。
- **改进建议**：
  1. 在 `_safe_rel_path` 与 `kb_delete_doc` 显式拒绝 `Path.drive` 非空、`Path.root` 非空、包含 `:` 或控制字符的输入；
  2. 写入与删除前强制断言 `dest.resolve().is_relative_to(kb_dir.resolve())`（`indexer.remove_file` 内部同步设防）；
  3. 补充 Windows 驱动器相对路径（覆盖 `subdir` 与 `filename`）和 symlink 逃逸单元测试。

#### P0-2 [运行时崩溃] `ApplicationsTable` 渲染期调用 `crypto.randomUUID()`，局域网 HTTP 环境编辑待办白屏崩溃
- **位置**：[`frontend/src/components/job-tracker/ApplicationsTable.tsx:86-102,311-314`](../frontend/src/components/job-tracker/ApplicationsTable.tsx#L86-L102)
- **问题分析**：
  - `todosFromText()` 在 `useMemo` 渲染期直接调用 `crypto.randomUUID()`（全仓唯一一处调用）。浏览器仅在 Secure Context（HTTPS 或 `localhost`）暴露 `crypto.randomUUID`，局域网通过 `http://<LAN-IP>:18080` 扫码访问时该方法为 `undefined`，用户在求职看板新增任意待办行会立刻抛出 `TypeError: crypto.randomUUID is not a function` 导致整页白屏（叠加 `main.tsx` 缺少 `ErrorBoundary`）。
  - 同时 `existingByTitle` 在存在两条相同标题待办时会碰撞复用同一 `id`。
- **改进建议**：
  1. 封装基于 `crypto.getRandomValues`（再退化至时间戳+随机数）的安全 UUID 工具函数；
  2. 将新 ID 生成移出渲染期 `useMemo`，改为在保存构造提交 payload 时生成，并按已消费索引避免同名待办复用同一 `id`。

### 4.3 P1 — 高优先级安全、数据完整性、并发与稳定性缺陷

#### P1-1 [安全/凭据泄漏] `GET/POST /api/config` 明文回传 3 项 STT 密钥及自定义 Header，`AppConfig` 缺 `repr=False`
- **位置**：[`backend/api/common/config_payload.py:57-58,62,64`](../backend/api/common/config_payload.py#L57-L64)、[`backend/core/config.py:214,216,223,226`](../backend/core/config.py#L214-L226)、[`frontend/src/components/settings/SpeechTab.tsx:13,15,22,24`](../frontend/src/components/settings/SpeechTab.tsx#L13-L24)
- **问题分析**：LLM `ModelConfig`/`ModelProvider` 与 `Mmpg` 均已脱敏为 `*_configured` 布尔标记并加了 `repr=False`，但 `build_config_payload()` 仍在每次 `GET/POST /api/config` 中明文回传 `doubao_stt_access_token`、`doubao_stt_api_key`、`generic_stt_api_key` 与可能含认证头的 `generic_stt_custom_headers`；`AppConfig` 对应 4 个字段亦缺少 `Field(default="", repr=False)`。
- **改进建议**：统一改为 `*_configured: bool` 返回模式（更新时留空保留原值、传 `null` 显式清除），4 字段补齐 `repr=False`；前端 `SpeechTab.tsx` 同步改为已配置占位提示。

#### P1-2 [安全/信息泄露] `POST /api/assist/preflight/replay` 允许任意 `audio_path` 探测本地/UNC 文件并借 STT 外泄 WAV 内容
- **位置**：[`backend/api/assist/routes.py:443-468`](../backend/api/assist/routes.py#L443-L468)、[`backend/api/assist/sound_test.py:154-160`](../backend/api/assist/sound_test.py#L154-L160)、[`backend/services/audio.py:898-915`](../backend/services/audio.py#L898-L915)
- **问题分析**：请求体 `audio_path` 未校验即构造 `Path(audio_path)`。不存在时 HTTP 503 回显完整路径（文件存在性 Oracle）；非 WAV 存在文件抛 `wave.Error`；Windows 传 UNC 路径可触发 SMB 外联（NTLM 凭证泄漏）；任意本地 `.wav` 会经扬声器播放并被 loopback 捕获转写后在响应 `transcript` 中返回。
- **改进建议**：移除 HTTP 自由 `audio_path` 字段，改为白名单 `fixture_id`（或强制校验位于受控 fixture 目录内、`resolve().is_relative_to(...)`、`.wav` 后缀且拒绝 UNC 路径）。

#### P1-3 [安全/窗口劫持] Electron 缺 `sandbox`/外链导航拦截，且 3 处 `ReactMarkdown` 裸渲染 `<a>` 标签
- **位置**：[`desktop/main.js:444-493,508-630`](../desktop/main.js#L444-L493)、[`frontend/src/components/AnswerMarkdownContent.tsx:156-229`](../frontend/src/components/AnswerMarkdownContent.tsx#L156-L229)、[`frontend/src/components/ResumeOptimizer.tsx:271`](../frontend/src/components/ResumeOptimizer.tsx#L271)、[`frontend/src/components/review/ReviewSessionDetail.tsx:536`](../frontend/src/components/review/ReviewSessionDetail.tsx#L536)
- **问题分析**：`mainWindow` 与 `overlayWindow` 未显式开启 `sandbox: true`，也未注册 `webContents.setWindowOpenHandler` 与 `will-navigate` 拦截；除 `InterviewOverlay.tsx:38` 将 `<a>` 覆写为 `<span>` 外，实时回答、简历优化、面试复盘 3 处 `<ReactMarkdown>` 均未覆写 `<a>`，点击 LLM 输出的恶意链接会直接导航离开本地应用或弹窗。
- **改进建议**：两类窗口显式加 `sandbox: true`，统一配置 `setWindowOpenHandler(() => ({ action: 'deny' }))` 和同源 `will-navigate` 白名单（外部 `https:`/`http:` 链接按需走 `shell.openExternal`）；前端抽取共享安全 `MarkdownLink` 组件覆盖全部 3 处。
